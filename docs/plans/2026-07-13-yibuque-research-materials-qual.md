## A. 知情同意书（模板）

**研究名称**：衣不缺（Harmony Wardrobe）用户研究
**研究机构**：产品体验研究团队
**研究目的**：了解你管理衣橱、穿搭与购物记录的真实习惯与痛点，验证产品设计是否符合你的预期，帮助我们把产品做得更好用。

**你将参与什么**
- 形式：一对一深度访谈（约 60–75 分钟）和/或 可用性测试（约 60 分钟），在你的手机上进行真实操作。
- 记录：在研究征得你同意后，我们会对过程进行**录音 / 录屏**（仅记录操作与对话，不含无关隐私）。

**关于你的数据（隐私）**
- 本产品本身**完全本地运行、不联网、数据只存在你手机上**；研究团队另行收集的研究录音/笔记与你手机内的应用数据相互独立。
- 研究资料将**去标识化**（不出现姓名、手机号等直接身份信息），加密保存，仅用于本研究。
- 资料保留期限：研究结束后 **12 个月**内销毁录音；匿名化结论可能用于产品报告。
- 你有权在任意时刻**无条件退出**、要求删除你的研究资料，且不影响你使用该产品。

**自愿原则**：参与完全自愿，拒绝或退出不会带来任何不利后果。

## B. 深度访谈提纲（60–75 分钟 · 阶段一）

**目标 RQ**：RQ1（现状/痛点/JTBD）、RQ2（核心流程心智）、RQ3（IA 心智）、RQ4（动机/价值）、RQ5（包容/无障碍）
**方式**：半结构化，鼓励讲故事，多用追问（probes）而非诱导。

### 暖场（5 分钟）
- 先用 1 分钟介绍自己和访谈目的（"没有标准答案，聊你的真实习惯就好"）。
- 你平时怎么打理自己的衣服？简单聊聊。

### 第一部分　衣橱管理现状与痛点（20 分钟 · RQ1）
1. 你平时怎么管理自己的衣服和穿搭？用什么工具（手机相册 / 备忘录 / 其他 App / 纸笔 / 什么都不记）？
2. 最近一次让你觉得"不知道穿什么"或"找不到某件衣服"是什么场景？当时怎么解决的？
3. 买衣服前后，你会做记录或对比吗？怎么做的？
4. 管理衣服这件事里，最让你烦的是什么？（追问：整理耗时 / 找不到 / 搭配困难 / 冲动消费 / 其他）
5. **Jobs-to-be-Done**：你希望"把衣橱管好"这件事，最终帮你达成什么？

### 第二部分　心智与信息架构（15 分钟 · RQ2 / RQ3）
1. 如果有个 App 帮你管衣服，你期望打开首页第一眼看到什么？
2. （展示底部导航截图：衣柜 / 逛店 / 相机 / 套装 / 我的）你理解每一项是做什么的吗？会怎么用？
3. 对你来说，"套装"（一整套搭配）和"衣柜"（单件衣服）是同一件事，还是不同的？你怎么区分？
4. 如果你想记录"今天去哪家店试了什么"，你会去哪找入口？（观察是否想到相机/逛店）
5. 你会希望 App 帮你"回忆某天穿了什么 / 去了哪家店"吗？

### 第三部分　动机与持续使用（10 分钟 · RQ4）
1. 什么会让你**每天**打开这类 App？什么不会？
2. 如果它**完全不联网、数据只存在你手机里**，你放心吗？还是反而在意同步/备份？
3. "今天穿什么"这类智能提醒，对你有用吗？担心它不准吗？
4. 你会愿意把"逛店试穿"也记下来吗？还是觉得多此一举？

### 第四部分　包容与无障碍（5 分钟 · RQ5）
1. 你或身边人用手机时，遇到过看不清字、点或滑不准的情况吗？
2. 对字号、颜色对比、按钮大小，你有什么偏好或困扰？

### 收尾（5 分钟）
- 还有什么我们没问到、但你觉得重要的？
- 如果只能改产品一件事，你改什么？

**记录要求**：每个问题标记对应 RQ；原话用引号记录；捕捉情绪词（"烦""懒得""怕"）。

## C. 可用性测试会话指南与任务卡（60 分钟 · 阶段二）

**目标 RQ**：RQ2（核心流程可完成性）、RQ3（IA 可寻性）、RQ5（包容/校验反馈）
**设备**：已安装「衣不缺」调试包的 HarmonyOS 真机（或模拟器，见计划 W3 依赖说明）
**参与**：n=8–10，含 ≥2 名 45+ 用户、≥2 名无障碍需求用户
**角色**：1 名主持人（引导+追问）、1 名观察员（记时/记严重度）、1 名记录员（引语转录）

### 前置准备（5 分钟）
- 欢迎、舒适化；签署知情同意书；确认录音/录屏。
- 说明**出声思考法**（think-aloud）："边做边说出你在想什么，不用解释，卡住也照实说"。
- 背景快问：常用哪些记账/衣橱/穿搭类 App？手机型号与系统？自评数码熟练度（1–5）？

### 基线问题（10 分钟）
- 你之前怎么管理衣服/穿搭？（呼应访谈，确认心智）
- 你期待这个 App 的首页长什么样？

### 任务场景（35 分钟）
> 每个任务先读情景，不教操作；成功标准达成即记"完成"，超时/需提示/放弃记"未完成"并标严重度（Nielsen 0–4，见分析框架）。

**T1 录入单品（RQ2）**
- 情景："你刚买了件上衣，用相册里的一张图把它存进衣柜，写上名称和分类。"
- 成功标准：从相册选图 → 归类为"衣柜" → 填写并保存成功。
- 观测重点：选图后是否理解"分类为衣柜"；名称/分类/备注/购买信息字段是否清晰；中文标签是否易懂。

**T2 创建穿搭（RQ2 / RQ3）**
- 情景："搭一套通勤穿搭，从你已有的衣服里选 2–3 件组成一套。"
- 成功标准：创建套装 → 关联到已有衣物 → 保存并回到套装墙可见。
- 观测重点："套装"与"衣柜"是否混淆；"从衣柜选已有衣物"入口是否隐蔽；默认命名是否被理解。

**T3 记录逛店（RQ2）**
- 情景："周末去商场试了件外套，记录这次逛店：店名、商圈、试穿备注、配一张图。"
- 成功标准：归类为"店铺" → 填写并保存 → 逛店列表出现。
- 观测重点：逛店入口是否找得到；空态 vs 搜索无结果文案是否被区分理解。

**T4 查找衣物（RQ3 · 预期无卡点）**
- 情景："用搜索加分类，找出你那件白色上衣。"
- 成功标准：通过搜索+分类筛选定位到目标卡片。
- 观测重点：搜索与分类胶囊协同是否顺手；是否误入拍照/编辑页。

**T5 个人信息与校验（RQ5）**
- 情景："填写并保存你的身高、体重；然后故意输个负数或非数字，看会发生什么。"
- 成功标准：合法值保存回显；非法值出现就近错误提示且保存按钮禁用。
- 观测重点：错误提示是否清晰；保存中/成功反馈是否可见；触控目标是否够大。

**T6 信息架构可寻性（RQ3 · 无引导）**
- 情景 A："不教任何路径，请找到'记录一次逛店'的入口。"
- 情景 B："请找到'查看某天穿了什么 / 日历回顾'的入口。"
- 成功标准：无外部提示下准确定位。
- 观测重点：是否凭直觉选择底部导航；"日历/Today"当前非主入口是否造成迷失。

### 后置访谈（10 分钟）
- 用 **SUS 系统可用性量表（10 题）** 打分。
- 整体印象？最喜欢 / 最卡壳的环节？
- 如果给团队一句改进建议，是什么？
- 对比你之前管理衣服的方式，这个 App 会更想用还是更麻烦？

### 数据收集字段
- 量化：任务完成率、时长、错误数、SUS 总分（公式见分析框架）。
- 质性：think-aloud 原话、情绪标记、严重度评级（0–4）、典型引语。
- 系统：设备型号、系统版本、应用 commit、是否使用种子数据、失败截图路径。

> 提示：测试任务直接对应 `docs/qa/manual-test-script.md` 的真实流程，研究是在已有 QA 上补"真实用户"这一环，而非另起标准。
