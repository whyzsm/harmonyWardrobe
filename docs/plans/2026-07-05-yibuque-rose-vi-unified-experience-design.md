# 衣不缺 Rose VI 统一体验设计

## 背景

本轮目标是把 `衣不缺` 收敛为一个个人衣橱和逛店记录工具，而不是首页信息流、电商心愿单或社交穿搭产品。用户已确认采用当前 rose/pink VI，并选择完整主流程统一方案。

当前代码已经具备部分基础能力：

- 主导航为 `衣橱 / 相机 / 逛店`。
- 顶部有 `logo + 衣不缺` 与 `我的` 入口。
- 相机入口已改成先 `拍照 / 从相册选择`，再在补录页选择 `衣橱 / 美搭 / 店铺`。
- 衣橱、美搭、店铺、日历、个人信息的领域模型和 repository 基本存在。

需要继续统一的部分：

- `docs/background/yibuque-design.md` 仍保留黑白/蓝绿旧视觉描述，和当前 rose VI 不一致。
- 部分组件仍混用 `AppTheme` 与 `Yibuque*` token。
- `TodayPage`、`ShoppingPage`、`OutfitsPage`、`Wishlist*` 等旧页面仍存在，不能再作为主流程或用户心智出现。
- 一些页面仍有偏工程化文案、旧概念文案和不统一的表单/卡片样式。
- 拍照补录链路需要确保三类对象都能真正落库并回显。

## 产品定位

`衣不缺` 是一个本地优先的个人衣橱和逛店记录 App。核心价值是让女性用户在高频拍照之后，用最短路径补录一条有用记录，并在衣橱、每日穿搭和逛店记录里找回。

产品关键词：

- 个人衣橱
- 照片优先
- 衣服 / 美搭 / 店铺
- 逛店记录
- 每日穿搭日历
- 本地保存
- 温柔、精致、轻负担

不做：

- 社交推荐流、点赞、评论、关注、粉丝关系。
- 电商购物车、下单、比价和远端同步。
- 把 `心愿单`、`首页`、`逛街` 作为主导航心智。
- 拍照前要求用户先选择复杂类型和大量字段。

## Rose VI 方向

当前视觉方向使用 rose/pink VI，而不是旧黑白蓝绿合同。新视觉应该柔和但克制：以浅玫瑰背景、白色内容面、深玫瑰主操作、精致圆角和轻阴影为主。

语义色方向：

- 页面背景：极浅玫瑰或 rose 渐变，避免大面积高饱和粉。
- 卡片：接近白色，保留轻微暖色。
- 主操作：深玫瑰 `#B11B68` 或更深 pressed 态。
- 标题：深葡萄棕 `#391327`，保证层级和可读性。
- 元信息：灰玫瑰 `#8A536B` / `#B9879E`。
- 边框：浅玫瑰，不用硬黑线。
- 占位：浅玫瑰、浅紫玫瑰、柔白粉。

视觉规则：

- 页面不要一片粉色，内容面必须靠白卡和图片建立呼吸感。
- 图片优先，卡片的第一视觉应是照片或柔和占位。
- 主按钮使用深玫瑰胶囊，不回到黑色主按钮。
- 大圆角用于卡片、图片、底部 sheet、主按钮。
- 轻阴影只能做层次，不做厚重电商卡片。
- 图标以线性、深玫瑰或深文本色为主。

## 组件系统

### AppTopBar

用途：一级页面统一顶部。

要求：

- 左侧为 app icon / logo mark 和 `衣不缺`。
- 右侧为头像或 `我的` 入口。
- 高度约 56，触达区域至少 44。
- 页面滚动时不遮挡主体内容。
- 不展示推荐、活动、社交入口。

### BottomNavigationBar

用途：主导航。

要求：

- 仅包含 `衣橱`、中间相机按钮、`逛店`。
- 中间按钮是明确相机/拍照 icon，不再是抽象 `+` 文案心智。
- 点击中间按钮打开 `QuickCaptureSheet`。
- 选中态用形状、字重和颜色共同表达。
- 底部保留安全区。

### QuickCaptureSheet

用途：照片来源选择。

要求：

- 只提供 `拍照` 和 `从相册选择`。
- 不在 sheet 中出现 `拍衣服`、`拍搭配`、`拍店铺`。
- 选择照片后再进入补录页选择 `衣橱 / 美搭 / 店铺`。
- 需要 loading/disabled 态，防止重复点击。

### CaptureEditPage

用途：照片补录。

要求：

- 顶部展示照片和拍照日期。
- 类型切换为 `衣橱 / 美搭 / 店铺`。
- `照片` 是唯一强必填项。
- `小记` 是核心输入，用多行文本框承载。
- 衣橱：名称自动生成，分类和购买信息选填。
- 美搭：标题自动生成，可选关联衣物，可选同步到日历。
- 店铺：店名自动生成，地址、日期选填。
- 保存后必须落到对应 repository，并回到对应列表。

### Cards

统一卡片规则：

- 图片或占位在上，信息在下。
- 图片圆角 20-28。
- 卡片圆角 24-32。
- 标题深色加粗。
- 元信息最多两行，避免密集。
- 空图占位使用浅 rose/purple/soft white，不使用硬灰空框。

### Forms

统一表单规则：

- 字段标签不能只依赖 placeholder。
- 选填字段在视觉上收纳进 `选填信息` 卡片。
- 错误信息靠近保存区或字段。
- 保存按钮有 loading 状态并防重复提交。
- 文案用用户语言，不出现 `wornDate`、`placeText` 这类字段名。

## 核心流程

### 拍衣服

1. 用户点击底部相机。
2. 选择 `拍照` 或 `从相册选择`。
3. 进入补录页，默认类型为 `衣橱`。
4. 系统基于分类和拍照日期生成名称，例如 `上衣 07-05 21:30`。
5. 用户可以只写小记，也可以补分类、价格、购买店铺等。
6. 保存后进入衣橱 `衣橱` tab，列表展示新增记录和照片。

### 拍美搭

1. 用户点击底部相机。
2. 选择照片。
3. 补录页切换到 `美搭`。
4. 系统生成标题，例如 `美搭 07-05 21:30`。
5. 用户可选关联衣物和同步到日历。
6. 保存后进入衣橱 `美搭` tab 或至少衣橱主区域可见新增记录。

### 拍店铺

1. 用户点击底部相机。
2. 选择照片。
3. 补录页切换到 `店铺`。
4. 系统生成店铺记录名，例如 `逛店 07-05 21:30`。
5. 用户可补商圈/地址和小记。
6. 保存后进入 `逛店` tab，列表展示新增记录。

### 日历

1. 衣橱内保留 `日历` tab。
2. 美搭补录可选同步到日历。
3. 日历按日期展示穿搭照片和小记。
4. 图册或记录要保留拍照日期，用于后续按日期整理。

## 数据与落库

保留本地优先架构：

- SQLite 是业务数据源。
- Search index 是派生数据。
- 照片二进制只保存在 app-local storage，SQLite 只保存 URI/path。
- 保存衣物、美搭、逛店记录时同步维护搜索索引。
- 旧 wishlist 表可以保留以避免迁移破坏，但主流程和搜索文案不能暴露为心愿单。

关键数据行为：

- `CaptureEditPage` 对 `initialPhotoUris` 做拷贝后写入 state，避免 readonly array/property 问题。
- 拍照和相册 URI 先经过 `PhotoStorage.copyToAppStorage`，再传给补录页。
- 店铺保存时，有店名则查找或创建 `Store`；无店名也必须创建 `StoreVisit`。
- 美搭保存时，即使未关联衣物，也可凭照片和自动标题保存。
- 同步日历只在用户启用或填写日期时创建 `WearLog`。

## 状态设计

每个主页面必须具备：

- Loading：初始化、加载列表、保存中。
- Empty：明确引导底部相机入口。
- Error：显示可理解错误和重试/取消路径。
- Disabled：保存中和无照片时禁用保存。
- Pressed：主按钮、底部相机、头像入口有轻微反馈。
