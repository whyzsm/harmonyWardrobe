# 衣不缺照片优先捕获与日历设计

Date: 2026-07-04

## 背景

`衣不缺` 的高频场景不是先填表，而是先拍照：看到衣服、穿好一套搭配、逛到一家店，用户第一反应都是留下照片，之后再补一句小记。当前 `+` 先让用户选择 `拍衣服 / 拍搭配 / 拍店铺`，再进入不同表单选图，链路过长；店铺记录还被店铺名必填挡住，导致用户感觉没有落库。

本设计把底部中心入口改为照片优先的统一捕获流，并把衣橱内部扩展为 `衣橱 / 美搭 / 日历`，用于管理单品、搭配和每日穿搭记录。

## 已确认需求

- 采用照片优先的统一捕获方案。
- 捕获后的类型固定为：`衣橱`、`美搭`、`店铺`。
- `衣橱` 在数据层保存为单件衣物。
- `美搭` 保存为搭配记录。
- `店铺` 保存为逛店记录，并可关联或生成店铺。
- 衣橱页增加 `日历` tab。
- 日历可按日期记录每日穿搭。
- 图册/照片记录需要自动带出拍照日期。
- 核心录入是 `照片 + 小记`，结构化信息全部选填。

## 目标

1. 把底部中心入口变成最快的拍照入口。
2. 拍照或选图完成后，再让用户判断这张照片属于 `衣橱 / 美搭 / 店铺`。
3. 三类补录页面保持同一套交互骨架：照片预览、类型选择、小记、选填信息、保存。
4. `拍美搭` 和 `拍店铺` 必须真正落库，并在对应列表回显。
5. 衣橱内提供 `日历`，记录每日穿搭，不恢复旧底部 `日历` 主导航。
6. 继续沿用现有 ArkUI、SQLite、Repository、PhotoStorage 和 Yibuque token 体系。

## 非目标

- 不新增独立 `同款` 类型。
- 不把 `日历` 放回底部主导航。
- 不做社交、推荐流、点赞、收藏、评论。
- 不新增网络接口、登录体系或云同步。
- 不强制依赖 EXIF 读取作为第一版前置条件。
- 不把照片二进制写入 SQLite。

## 方案比较

### 方案 A：保留三个编辑页，只把入口改成先拍照

入口变短，改动较小。但 `衣橱`、`美搭`、`店铺` 仍然分别维护表单和校验，体验容易继续不一致，后续每次优化都要改三处。

结论：不推荐作为主方案。

### 方案 B：新增统一捕获流，按类型保存到现有 Repository

新增一个统一捕获页或捕获组件：底部中心相机入口先完成 `拍照 / 从相册选择`，拿到照片后进入统一补录页。补录页选择 `衣橱 / 美搭 / 店铺`，核心输入为小记，选填字段按类型展开，最终调用现有 `ClothingRepository`、`OutfitRepository`、`StoreRepository`、`WearLogRepository` 保存。

结论：推荐。体验统一，数据边界清楚，改动可控。

### 方案 C：拍照后立即保存草稿，再异步补录

数据安全最好，用户不会丢照片。但需要新增草稿状态、草稿列表、草稿清理和迁移策略，超出当前阶段。

结论：后续可做，不作为第一版。

## 推荐方案

采用方案 B：新增照片优先统一捕获流。

底部中心按钮从 `+` 变为相机图标。点击后先提供两个动作：

- `拍照`
- `从相册选择`

拿到照片后进入统一补录页：

```text
照片预览
[衣橱] [美搭] [店铺]
小记（多行文本框）
选填信息
保存
```

## 核心流程

### 新增衣橱照片

1. 点击底部相机。
2. 选择 `拍照` 或 `从相册选择`。
3. 进入补录页，默认类型为 `衣橱`。
4. 系统显示照片和默认日期。
5. 用户可填写小记。
6. 选填信息包括：名称、分类、购买店铺、价格、购买日期、购买备注。
7. 名称为空时自动生成，例如 `上衣 07-04 18:20`。
8. 保存后创建衣物，回到衣橱列表并刷新。

### 新增美搭

1. 点击底部相机并获取照片。
2. 在补录页切换类型为 `美搭`。
3. 用户可填写小记。
4. 选填信息包括：美搭名称、关联衣物、穿搭日期。
5. 名称为空时自动生成，例如 `美搭 07-04 18:20`。
6. 保存后创建美搭，并可选择同步生成一条每日穿搭记录。

第一版建议默认只保存美搭；如果用户在选填区开启或填写穿搭日期，再创建 `WearLog`。

### 新增店铺

1. 点击底部相机并获取照片。
2. 在补录页切换类型为 `店铺`。
3. 用户可填写小记。
4. 选填信息包括：店铺名、商圈/地址、逛店日期。
5. 店铺名为空时保存为 `未命名店铺` 或 `逛店 07-04 18:20`。
6. 保存后创建逛店记录，回到逛店列表并刷新。

## 日历设计

`日历` 是衣橱页内部 tab，不是底部主导航。

日历展示内容：

- 月视图日期格。
- 有穿搭记录的日期显示小圆点或照片缩略提示。
- 选中日期后展示当天穿搭记录列表。
- 当天没有记录时展示轻量空态：`今天穿了什么？从相机记录一套。`
- 支持手动补记当天或历史日期。

日历数据来源：

- 使用现有 `WearLogRepository`。
- `WearLog.wornDate` 是每日穿搭日期。
- `WearLog.photoUris` 存放穿搭照片。
- `WearLog.note` 存放小记。
- `WearLog.outfitTemplateId` 可选，不强制必须绑定美搭。

第一版保存规则：

- 从捕获流保存为 `美搭` 时，不强制生成日历记录。
- 用户填写或确认 `穿搭日期` 时，可同步创建 `WearLog`。
- 从日历 tab 补记时，默认类型是每日穿搭记录，照片和小记必优先展示，关联美搭可选。

## 拍照日期规则

捕获流维护一个 `capturedAt` 或等价的本地时间字段。

第一版规则：

- 相机拍照成功：`capturedAt` 使用拍照成功时刻。
- 相册选择成功：`capturedAt` 使用选图成功时刻。
- 默认日期字段从 `capturedAt` 推导。
- 用户可在选填信息里修改衣物购买日期、逛店日期或穿搭日期。

后续增强：

- 如果 HarmonyOS 能稳定提供照片原始创建时间或 EXIF 拍摄时间，再优先使用照片原始拍摄时间。
- 无法读取原始拍摄时间时继续回退到捕获时间。

## 组件职责

### BottomNavigationBar

- 中间按钮从 `+` 改为相机图标。
- 保持 44 以上触达区域。
- 点击回调命名为照片捕获语义，例如 `onOpenCapture`。

### QuickCaptureSheet

- 从三类业务动作改为照片来源动作。
- 只提供 `拍照`、`从相册选择` 和取消。
- 不再在这里选择 `衣橱 / 美搭 / 店铺`。

### CaptureEditPage

新增统一捕获补录页。

职责：

- 接收初始照片、本地照片 URI 和捕获时间。
- 展示照片预览。
- 管理类型选择：`衣橱 / 美搭 / 店铺`。
- 管理小记。
- 展示各类型选填信息。
- 保存时路由到对应 repository。
- 保存成功后通知 `Index` 切回对应主页面和 tab。

### WardrobePage

- 二级 tab 改为 `衣橱 / 美搭 / 日历`。
- `衣橱` 展示衣物列表和分类筛选。
- `美搭` 展示搭配列表。
- `日历` 内嵌日历视图和当日穿搭记录。

### StoreVisitPage

- 保存店铺类型后刷新逛店记录。
- 空店铺名记录也必须展示。

## 数据流

```text
Bottom camera button
  -> QuickCaptureSheet
  -> PhotoPickerAdapter.captureFromCamera / pickFromGallery
  -> PhotoStorage.copyToAppStorage
  -> CaptureEditPage
  -> ClothingRepository.createClothing
     OutfitRepository.createOutfit
     StoreRepository.createStoreVisit
     WearLogRepository.createWearLog
  -> Index refreshes selected page
```

## 校验规则

- 所有类型都要求至少一张照片。
- 小记选填，但在视觉上优先展示。
- `衣橱` 名称选填，空值自动生成。
- `美搭` 名称选填，空值自动生成。
- `店铺` 店铺名选填，空值自动生成。
- 分类、关联衣物、地址、日期、价格均选填。
- 保存按钮只有在照片可用且未保存中时启用。

## 视觉与交互规则

- 使用 `docs/background/yibuque-design.md` 和 `Tokens.ets` 中的 Yibuque token。
- 主按钮黑底白字，胶囊，高度 56。
- 类型选择为胶囊分段控件，选中黑色描边或黑底白字。
- 小记是多行文本框，高度不低于 96。
- 选填信息默认收起或放在次级区域，不抢占小记。
- 照片预览大圆角，优先占据首屏视觉。
- 页面保留轻微入场动画和按压反馈，但不做复杂动效。

## 错误处理

- 用户取消拍照或选图：关闭 Sheet，不进入补录页。
- 照片复制失败：提示 `照片保存失败，请重新选择`，不创建记录。
- Repository 保存失败：停留在补录页并显示错误。
- 店铺名为空不报错，使用默认名称保存。
- 美搭未关联衣物不报错。
- 日历记录未关联美搭不报错。

## 交付边界

第一版完成后，用户应能：

- 从底部相机一键开始拍照或选图。
- 拍完后选择保存为衣橱、美搭或店铺。
- 只填小记也能保存。
- 在衣橱列表看到衣物。
- 在美搭列表看到搭配。
- 在逛店列表看到店铺/逛店记录。
- 在衣橱的日历 tab 查看和补记每日穿搭。
